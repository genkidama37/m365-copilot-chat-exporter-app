Lesson 0002: Tracing SQLite Persistence, Transactions & Relational Reconstruction

How SqliteConversationRepository.cs saves and reconstructs immutable Conversation graphs using Microsoft.Data.Sqlite.

Mission Link: Behind the ICopilotExportService seam sits SqliteConversationRepository. Mastering how it handles transactions, parameters, timestamps, and multi-table reads lets you catch data-corruption bugs and N+1 query bottlenecks in agent diffs.

1. Schema, Foreign Keys & Raw String Literals ("""...""")

Open src/CopilotChatExporter.Core/Persistence/SqliteConversationRepository.cs and look at InitializeSchemaAsync (lines 17–51): 

public async Task InitializeSchemaAsync(CancellationToken cancellationToken = default)
{
    await using var command = _connection.CreateCommand();
    command.CommandText = """
        PRAGMA foreign_keys = ON;

        CREATE TABLE IF NOT EXISTS conversations (
            id TEXT PRIMARY KEY,
            title TEXT NOT NULL,
            created_at TEXT NOT NULL,
            updated_at TEXT NOT NULL
        );

        CREATE TABLE IF NOT EXISTS turns (
            id TEXT PRIMARY KEY,
            conversation_id TEXT NOT NULL,
            sequence_number INTEGER NOT NULL,
            prompt TEXT NOT NULL,
            response TEXT NOT NULL,
            created_at TEXT NOT NULL,
            FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE
        );
        ...
        """;
    await command.ExecuteNonQueryAsync(cancellationToken);
}

Two details are worth noting here:

  • Raw String Literals (""" ... """): Introduced in C# 11, triple-quoted strings work like Python's textwrap.dedent("""...""") or Java text blocks. The compiler automatically strips all leading spaces up to the horizontal column of the closing """, and you never need to escape quotes inside the string.
  • PRAGMA foreign_keys = ON + ON DELETE CASCADE: In SQLite (Microsoft Learn: Microsoft.Data.Sqlite), foreign-key constraints are disabled by default until PRAGMA foreign_keys = ON; is executed on the connection. Because turns.conversation_id references conversations(id) ON DELETE CASCADE (and citations.turn_id references turns(id) ON DELETE CASCADE), deleting one row in conversations automatically deletes all of its child rows in turns and citations.

2. Atomic Upserts: Transactions, Block-Scoped await using & ISO-8601 Timestamps

Look at how SaveConversationAsync (lines 53–119) saves or updates a conversation: 

public async Task SaveConversationAsync(Conversation conversation, CancellationToken cancellationToken = default)
{
    ArgumentNullException.ThrowIfNull(conversation);

    await EnableForeignKeysAsync(cancellationToken);
    await using var transaction = (SqliteTransaction)await _connection.BeginTransactionAsync(cancellationToken);

    await using (var deleteExistingCmd = _connection.CreateCommand())
    {
        deleteExistingCmd.Transaction = transaction;
        deleteExistingCmd.CommandText = "DELETE FROM conversations WHERE id = $id;";
        deleteExistingCmd.Parameters.AddWithValue("$id", conversation.Id);
        await deleteExistingCmd.ExecuteNonQueryAsync(cancellationToken);
    }

    await using (var insertConversationCmd = _connection.CreateCommand())
    {
        insertConversationCmd.Transaction = transaction;
        insertConversationCmd.CommandText = """
            INSERT INTO conversations (id, title, created_at, updated_at)
            VALUES ($id, $title, $created_at, $updated_at);
            """;
        insertConversationCmd.Parameters.AddWithValue("$id", conversation.Id);
        insertConversationCmd.Parameters.AddWithValue("$title", conversation.Title);
        insertConversationCmd.Parameters.AddWithValue("$created_at", conversation.CreatedAt.ToString("O", CultureInfo.InvariantCulture));
        insertConversationCmd.Parameters.AddWithValue("$updated_at", conversation.UpdatedAt.ToString("O", CultureInfo.InvariantCulture));
        await insertConversationCmd.ExecuteNonQueryAsync(cancellationToken);
    }
    // ... inserts turns and citations in a loop ...

    await transaction.CommitAsync(cancellationToken);
}

Notice four deliberate patterns working together:

  1. Delete-Then-Insert inside a Transaction: If you ingest "conv-001" a second time with updated turns, DELETE FROM conversations WHERE id = $id; cascades to wipe out the old turns and citations, and then the new rows are inserted. Because both happen inside transaction, no caller ever sees a half-deleted conversation.
  2. Automatic Rollback via await using var transaction: Remember from Lesson 0001 that await using var transaction wraps the rest of the method in try { ... } finally { await transaction.DisposeAsync(); }. In Microsoft.Data.Sqlite, if an exception is thrown before await transaction.CommitAsync(cancellationToken) is called, transaction.DisposeAsync() automatically rolls back the entire transaction—leaving the database untouched.
  3. Block-Scoped await using (var cmd = ...) { ... }: Why does deleteExistingCmd have explicit { ... } braces around it while transaction does not? Because transaction must stay alive for the whole method, whereas each SqliteCommand should be disposed as soon as its query finishes, before creating the next command on the same connection.
  4. Parameterized SQL ($id) & ISO-8601 Round-Trip ("O"):
    • Parameters.AddWithValue("$id", conversation.Id) binds parameters safely so a title containing quotes or SQL keywords never causes SQL injection or syntax errors.
    • SQLite stores timestamps as TEXT. Calling conversation.CreatedAt.ToString("O", CultureInfo.InvariantCulture) formats the timestamp using .NET's round-trip ISO-8601 specifier ("O") (e.g., "2026-03-15T09:30:00.0000000+00:00"), and CultureInfo.InvariantCulture guarantees that the user's OS locale settings never alter date separators or digits.

3. Reading Rows & Preventing N+1 Queries (GetAllConversationsAsync)

When reading rows back, await cmd.ExecuteReaderAsync(cancellationToken) returns a SqliteDataReader—a forward-only cursor that starts positioned before the first row. Each call to await reader.ReadAsync(cancellationToken) advances to the next row and returns true (or false when no rows remain), and reader.GetString(0) / reader.GetInt32(1) reads column values by their zero-based position in the SELECT clause.

Now compare loading a single conversation (GetConversationAsync) with loading the entire catalog (GetAllConversationsAsync, lines 210–304). If GetAllConversationsAsync looped over 500 conversations and ran nested SELECT queries for each conversation's turns and each turn's citations, it would execute thousands of queries (the classic N+1 query problem). Instead, it runs 3 flat queries total and stitches them together in memory: 

// 1. Named Value Tuple list: lightweight row buffer (like Array<{ Id: string, Title: string, ... }> in TypeScript)
var conversationRows = new List<(string Id, string Title, DateTimeOffset CreatedAt, DateTimeOffset UpdatedAt)>();

// 2. Group all citations by turn_id in a Dictionary
var citationsByTurnId = new Dictionary<string, List<Citation>>(StringComparer.Ordinal);
// ... populates citationsByTurnId from 'SELECT turn_id, id, title, url FROM citations ...'

// 3. Look up each turn's citations safely with TryGetValue
var citations = citationsByTurnId.TryGetValue(turnId, out var turnCitations)
    ? (IReadOnlyList<Citation>)turnCitations
    : [];

Look closely at those two C# constructs:

  • Named Value Tuples ((string Id, string Title, ...)): When you need a temporary row shape inside a method without declaring a whole new record file, C# lets you write parenthesized types with field names. You construct one with (reader.GetString(0), reader.GetString(1), ...) and read its fields by name (`row.Id`, `row.Title`).
  • Dictionary.TryGetValue(key, out var value) vs. dict[key]: In JavaScript/TypeScript, looking up a missing key on an object or Map returns undefined. In C#, indexing citationsByTurnId[turnId] on a missing key throws a KeyNotFoundException! Because a turn with zero citations has zero rows in the citations table, its turnId will not exist in citationsByTurnId. Calling citationsByTurnId.TryGetValue(turnId, out var turnCitations) performs a single hash lookup that returns true (and assigns the new variable turnCitations) if found, or returns false so we can fall back to the empty collection expression [].
